# Claude Code Agent View — Managing Multiple Background Sessions

**Source:** [Manage multiple agents with agent view](https://code.claude.com/docs/en/agent-view)

---

## Summary

Agent view (`claude agents`) is a full-terminal dashboard for dispatching and managing many Claude Code background sessions from one screen. Each background session is a full Claude Code conversation that keeps running without a terminal attached — the developer dispatches tasks, checks state at a glance, peeks at outputs, and intervenes only when a session needs input. Sessions are hosted by a per-user supervisor process independent of any terminal. Requires Claude Code v2.1.139+.

## Core Concept

Use agent view when you have several independent tasks Claude can work on without you watching every step. Dispatch a bug fix, a PR review, and a flaky-test investigation as three rows; keep working in another window; check back when a row shows it needs you or has a result (source: 2026-05-25-Manage multiple agents with agent view.md).

## Session States

Each row shows an icon whose color and animation indicate state:

| State | Icon | Meaning |
|---|---|---|
| Working | Animated | Claude is actively running tools or generating a response |
| Needs input | Yellow | Waiting on a question or permission decision |
| Idle | Dimmed | Nothing to do; ready for next prompt |
| Completed | Green | Task finished successfully |
| Failed | Red | Task ended with an error |
| Stopped | Grey | Stopped with `Ctrl+X` or `claude stop` |

Icon shape separately indicates whether the **process** is alive:
- `✻` / animated `✽` — process alive, replies immediately
- `∙` — process has exited; peek/reply/attach will restart from where it left off
- `✢` — a `/loop` session sleeping between iterations; row shows run count and countdown

(source: 2026-05-25-Manage multiple agents with agent view.md)

## Key Interactions

**Peek and reply (`Space`).** Opens a panel showing what the session needs, recent output, and any PRs it opened. Type a reply and press `Enter`. For multiple-choice questions, press a number key. For blocked sessions, `Tab` fills a suggested reply to edit. Usually sufficient — no need to open the full transcript (source: 2026-05-25-Manage multiple agents with agent view.md).

**Attach (`Enter` / `→`).** Replaces agent view with the full interactive session. Claude posts a recap of what happened while you were away. Press `←` on an empty prompt to detach and return to agent view. Detaching never stops a background session (source: 2026-05-25-Manage multiple agents with agent view.md).

**Row summaries.** Generated by a Haiku-class model, refreshed at most every 15 seconds plus once per turn end. Each refresh is one short Haiku request billed under normal data usage terms (source: 2026-05-25-Manage multiple agents with agent view.md).

**PR status dot.** When a session opens a PR, a colored dot appears (yellow = waiting/failed checks; green = checks passed; purple = merged; grey = draft/closed). For most tasks, this is where you pick up the result: review and merge when the dot turns green (source: 2026-05-25-Manage multiple agents with agent view.md).

## Dispatching New Agents

**From agent view input:** type a prompt and press `Enter`. The session is named automatically. Prefix/mention options:

| Input | Effect |
|---|---|
| `<agent-name> <prompt>` | Run named subagent as main agent |
| `@<agent-name>` | Mention a subagent anywhere in prompt |
| `@<repo>` | Run session in that repository |
| `/<skill>` | Suggest skills to dispatch as prompt |
| `Shift+Enter` | Dispatch and immediately attach |

**Backgrounding an existing session:** run `/bg` (or `/background`) inside any interactive session to move it into the background. Flags from the original launch (`--mcp-config`, `--settings`, `--add-dir`, etc.) carry through (source: 2026-05-25-Manage multiple agents with agent view.md).

**From shell:** `claude --bg "<prompt>"`. Combine with `--agent` for a named subagent, `--name` for a display name (source: 2026-05-25-Manage multiple agents with agent view.md).

**`←` shortcut from any session:** pressing `←` on an empty prompt from any Claude Code session backgrounds it and opens agent view with that row selected — switch sessions without leaving the terminal (source: 2026-05-25-Manage multiple agents with agent view.md).

## File Edit Isolation via Git Worktrees

Every background session automatically moves into an isolated git worktree under `.claude/worktrees/` before editing files. Parallel sessions can read the same checkout but each writes to its own tree (source: 2026-05-25-Manage multiple agents with agent view.md).

Worktree isolation is skipped when:
- The session is already inside a linked git worktree
- The working directory is not a git repository
- The write is outside the working directory

To disable for repos where worktrees are impractical, set `"worktree": {"bgIsolation": "none"}` in `.claude/settings.json` (requires v2.1.143+). **Warning:** deleting a session in agent view removes the worktree Claude created for it, including uncommitted changes — push or commit first (source: 2026-05-25-Manage multiple agents with agent view.md).

## The Supervisor Process

Background sessions are hosted by a per-user supervisor process separate from the terminal and from agent view itself. The supervisor:
- Starts automatically on first backgrounded session or `claude agents`
- Keeps active sessions running (active = working, waiting for input, or attached terminal)
- Stops idle non-pinned processes after ~1 hour; the session restarts from saved state on next interaction
- Preserves sessions across machine sleep; stops them on shutdown
- Watches the installed Claude Code binary and restarts into new version after auto-updates
- Manages memory pressure by stopping idle non-pinned sessions first

Pin a session with `Ctrl+T` to keep its process alive while idle (source: 2026-05-25-Manage multiple agents with agent view.md).

## Shell Management Commands

| Command | Purpose |
|---|---|
| `claude agents` | Open agent view |
| `claude agents --cwd <path>` | Scope to sessions under `<path>` |
| `claude agents --json` | Print live sessions as JSON and exit |
| `claude attach <id>` | Attach in current terminal |
| `claude logs <id>` | Print recent output |
| `claude stop <id>` | Stop a session |
| `claude respawn <id>` | Restart with conversation intact |
| `claude respawn --all` | Restart all running sessions (e.g. after update) |
| `claude rm <id>` | Remove from list |
| `claude daemon status` | Print supervisor state, version, socket, worker count |

(source: 2026-05-25-Manage multiple agents with agent view.md)

## Permission, Model, and Effort Defaults

Pass `--permission-mode`, `--model`, or `--effort` when opening agent view to set defaults for all sessions dispatched from it. Displayed in the footer below the dispatch input (requires v2.1.142+):

```bash
claude agents --permission-mode plan --model opus --effort high
```

`bypassPermissions` and `auto` modes require one-time interactive acceptance before background sessions can use them (source: 2026-05-25-Manage multiple agents with agent view.md).

## Limitations (Research Preview)

- **Rate limits apply**: parallel sessions consume quota proportionally
- **Sessions are local**: run on your machine; preserved across sleep but stop on shutdown
- **Worktree deletion**: deleting a session in agent view removes its Claude-created worktree including uncommitted changes

(source: 2026-05-25-Manage multiple agents with agent view.md)

## Key Takeaways

- Agent view is the multi-session control plane: dispatch many tasks, attend only when a row asks for you
- The peek panel handles most interventions without opening the full transcript
- Git worktree isolation prevents parallel sessions from clobbering each other's writes
- The supervisor process keeps sessions alive independent of any terminal or agent view window
- Use `claude agents --json` to script agent fleet monitoring
