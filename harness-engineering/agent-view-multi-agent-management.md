# Agent View — Managing Multiple Claude Code Sessions from One Screen

**Source:** [Manage multiple agents with agent view](https://code.claude.com/docs/en/agent-view)

---

## Summary

Agent view (`claude agents`) is a terminal UI for dispatching and managing many Claude Code background sessions from one screen. It shows each session's state, provides a peek panel for lightweight interaction, and lets you attach to the full conversation when needed. Background sessions run via a supervisor process independent of any terminal, so they keep working when you close the window or switch tasks.

## Core Concept

Agent view is the right tool when you have several independent tasks Claude can work on in parallel without you watching every step. Dispatch a bug fix, a PR review, and a flaky-test investigation as three rows, keep working elsewhere, and check back when a row signals it needs you or has a result (source: agent-view-multi-agent-management.md).

Requires Claude Code v2.1.139 or later. Currently in research preview — interface and keyboard shortcuts may change (source: agent-view-multi-agent-management.md).

## Reading Session State

Each row in agent view shows an icon whose color and animation indicate state (source: agent-view-multi-agent-management.md):

| State | Icon | Meaning |
|---|---|---|
| Working | Animated | Claude is actively running tools or generating |
| Needs input | Yellow | Waiting on a question or permission decision |
| Idle | Dimmed | Ready for next prompt |
| Completed | Green | Task finished successfully |
| Failed | Red | Task ended with an error |
| Stopped | Grey | Stopped with Ctrl+X or `claude stop` |

Icon shape indicates whether the process is alive: `✻`/`✽` = alive, `∙` = process exited (can still attach; Claude restarts from where it left off), `✢` = `/loop` session sleeping between iterations (source: agent-view-multi-agent-management.md).

Row summaries are generated by a Haiku-class model — refreshed at most every 15 seconds while working, plus once per turn end. A pull request status dot appears at the row's right edge when a session opens a PR (source: agent-view-multi-agent-management.md).

## Peek and Reply

Press `Space` on a selected row to open the peek panel: shows what the session needs, its most recent output, and any open PRs. Type a reply and press `Enter` to send it. Most of the time the peek panel is enough — you never need to open the full transcript (source: agent-view-multi-agent-management.md).

Prefix a reply with `!` to send a Bash command instead of a message. Use `Tab` to fill the input with a suggested reply. Use `↑`/`↓` to peek adjacent sessions, or `→` to attach (source: agent-view-multi-agent-management.md).

## Attaching and Detaching

Press `Enter` or `→` to attach to a session — agent view is replaced by the full interactive conversation. When you attach, Claude posts a short recap of what happened while you were away (source: agent-view-multi-agent-management.md).

Press `←` on an empty prompt to detach and return to agent view. Detaching never stops the background session: `←`, `Ctrl+C`, `Ctrl+D`, `Ctrl+Z`, and `/exit` all leave it running. To stop a session from inside, run `/stop` (source: agent-view-multi-agent-management.md).

`←` also works from any Claude Code session, not only ones attached from agent view — it backgrounds the current session and opens agent view with that row selected (source: agent-view-multi-agent-management.md).

## Dispatching New Sessions

**From agent view**: type a prompt in the input at the bottom and press `Enter`. The session is named from the prompt automatically. Dispatch shortcuts (source: agent-view-multi-agent-management.md):

| Input prefix | Effect |
|---|---|
| `<agent-name>` as first word | Run that subagent as the main agent |
| `@<agent-name>` | Mention a subagent anywhere in the prompt |
| `@<repo>` | Run the session in the mentioned repository |
| `/<skill>` | Suggest skills to dispatch as the prompt |
| `Shift+Enter` | Dispatch and immediately attach |

**From inside a session**: run `/background` or `/bg` to move the conversation to a background session. Pass a prompt to give one more instruction first (source: agent-view-multi-agent-management.md).

**From the shell**: `claude --bg "<prompt>"` starts a session that goes straight to the background. Combine with `--agent` to run a specific subagent, `--name` to set display name, `--model` to set model (source: agent-view-multi-agent-management.md).

## File Edit Isolation via Git Worktrees

Every background session automatically moves into an isolated git worktree under `.claude/worktrees/` before editing files, so parallel sessions can read the same checkout but each writes to its own branch (source: agent-view-multi-agent-management.md).

Claude skips the worktree when the session is already inside a linked worktree, the directory isn't a git repo, or the write is outside the working directory. To disable worktree isolation: set `worktree.bgIsolation: "none"` in `.claude/settings.json` (requires v2.1.143+) (source: agent-view-multi-agent-management.md).

Deleting a session in agent view (`Ctrl+X` twice) removes the Claude-created worktree including uncommitted changes — merge or push first. The conversation transcript stays on disk and remains available via `claude --resume` (source: agent-view-multi-agent-management.md).

## The Supervisor Process

Background sessions are hosted by a per-user supervisor process separate from your terminal. The supervisor starts automatically the first time you background a session or open agent view. Sessions keep running when you close agent view or your shell (source: agent-view-multi-agent-management.md).

A session stays alive while: actively working, waiting on input, or with a terminal attached. A running background shell command, subagent, or monitor counts as active work. Sessions that finish and sit unattached for ~1 hour are stopped to free resources. Pin a session with `Ctrl+T` to exempt it from this cleanup (source: agent-view-multi-agent-management.md).

The supervisor watches the installed Claude Code binary and restarts into new versions after auto-update. Background sessions keep running through the restart (source: agent-view-multi-agent-management.md).

## Key Shell Commands

| Command | Purpose |
|---|---|
| `claude agents` | Open agent view |
| `claude agents --cwd <path>` | Scope to sessions under `<path>` |
| `claude agents --json` | Print live sessions as JSON array and exit |
| `claude attach <id>` | Attach to a session |
| `claude logs <id>` | Print recent output |
| `claude stop <id>` | Stop a session |
| `claude respawn <id>` | Restart with conversation intact |
| `claude respawn --all` | Restart all running sessions (e.g., after update) |
| `claude rm <id>` | Remove session from list |
| `claude daemon status` | Print supervisor state |

## Key Takeaways

- Agent view is the command center for parallel Claude Code work — dispatch, monitor, and step in as needed
- The peek panel handles most interactions; full attachment is rarely needed
- `←` from any session backgrounds it and opens agent view — use it as your primary navigation pattern
- Git worktrees provide automatic isolation for parallel sessions editing the same codebase
- The supervisor keeps sessions alive independently of terminals; sessions survive sleep and auto-updates
